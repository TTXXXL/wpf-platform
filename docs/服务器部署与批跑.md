# 服务器部署与批跑

## 环境

服务器容器的项目环境是 `/opt/conda/envs/wpf`：Python 3.12，torch 2.6.0+cu124，LightGBM 4.6。非交互 SSH 不会读 `.bashrc`，命令里一律写全路径 `/opt/conda/envs/wpf/bin/python`。

首次部署或代码更新后，在仓库根执行一次：

```bash
/opt/conda/envs/wpf/bin/python -m pip install --no-deps -e .
```

## 代码与数据

| 内容 | 怎么到服务器 |
|---|---|
| 代码、配置、文档 | 开发版 `wpf-benchmark/` 验证后运行 `scripts/sync_server_project.py`，生成 `wpf-benchmark-server/` 和上传 ZIP；在服务器版 Git 仓库提交后，服务器 `git pull`（或传 Git bundle） |
| SDWPF 原始 CSV | 随同步进入服务器版目录（`data/raw/sdwpf/`），在服务器上 `wpf-benchmark build sdwpf` 构建，约 1 分钟 |
| Kelmarsh、Penmanshiel | 原始压缩包有十几 GB，不同步。在本地构建后，把 `data/datasets/kelmarsh/` 和 `data/datasets/penmanshiel/` 两个目录（约 120 MB 和 210 MB）拷到服务器同一位置 |

`data/datasets/`、`results/` 不进 Git。拷过去的数据集用 `meta.json` 里的 `panel_sha256` 核对：

```bash
sha256sum data/datasets/*/panel.parquet
```

## 冒烟检查

服务器副本不含 `tests/`（同步脚本有意排除），完整测试只在开发版运行。服务器上用仓库自带的命令自检：

```bash
PY=/opt/conda/envs/wpf/bin/python
$PY -m wpf_benchmark build synthetic
$PY -m wpf_benchmark tasks                           # 各任务应为 ok 或 dataset not built
$PY -m wpf_benchmark study --plan server_smoke --preflight   # 加载数据、试建全部网络，退出码 0 才算通过
$PY -m wpf_benchmark study --plan server_smoke       # 12 个模型各训练 1 轮
```

开发版的测试结果（通过数、代码 SHA256）记在每次交付的改动说明里，服务器自检与它对照。

## 批跑

```bash
$PY -m wpf_benchmark study --plan baselines_v1 --preflight   # 只检查，不训练
nohup $PY -u -m wpf_benchmark study --plan baselines_v1 > results/baselines_v1.log 2>&1 &
```

- `--preflight` 会载入每个任务的数据（核对 `panel.parquet` 的哈希）、构建三个切分并统计实际预测窗口内的有效标签数，检查每个模型与任务的输入和窗口约束，并对神经网络试建网络、做一次小批量前向；问题按任务和模型列出，有问题时退出码为 1。它不训练，耗时主要在读数据。有效标签数按“窗口 × 时距 × 机组”计数，重叠窗口里的同一观测会重复计数。
- 中断后重跑同一条命令。组合只有在 `DONE` 清单与目录内容吻合，且运行身份（任务配置、模型及全部生效参数、种子、数据文件与元数据哈希）与当前一致时才跳过。
- 已完成但身份不一致（改过模型参数、任务配置或数据），或完成于身份机制出现之前的组合，批跑会列出并停下，不会静默复用。要重做加 `--rerun-stale`，否则换一个计划名。计划里新增任务或模型不受影响。
- 单个组合失败只记入 `failures.json` 和该组合的 `error.txt`，其余组合照常运行。
- 运行中的组合目录里有 `RUNNING` 文件。另一个进程碰到它会整批中止。确认原进程已不存在（例如被强制结束）后，手动删除该文件再续跑。
- 代码或数据集的 SHA256 与第一次运行时不同时，批跑会停下。确实要混用时加 `--allow-changed-code`，否则请换一个计划名。数据集哈希现在按文件内容重新计算，不再只读 `meta.json`。
- `--only kelmarsh` 只跑任务或模型名里含该文本的组合。
- 汇总和打包同样检查数据完整性，哈希不符会报错。若本机缺少数据文件，仍会根据结果中保存的数据身份检查当前任务和模型配置，并在 `summary.csv` 标记 `data_verified=False`；这不表示已经验证了本机数据。旧格式结果标为 `legacy`，身份不同的结果标为 `stale`，后者不填入评分数值。
- 结束后自动生成 `results/studies/<计划>/<计划>_delivery.zip`，回传这一个文件即可。它包含计划、`manifest.json`、`summary.csv`、`failures.json`，以及每个组合的 `run.json`、`metrics.json`、`per_horizon.csv`、`train.log`。预测和权重默认不打包，需要时用 `--package --include-predictions` 或 `--include-checkpoints` 重新打包。

## 与旧结果的兼容

旧格式 `DONE` 只保存指标文件哈希，新代码会将它识别为 `legacy`。可以汇总打包，但恢复训练时需要新建计划，或明确使用 `--rerun-stale` 重做。代码有变化还需要 `--allow-changed-code`。新指标将 `ramp` 改为 `ramp_change_detection`，并新增 `ramp_directional`，读取新旧结果的分析脚本需分别识别字段。
