# 评估

评估器（`evaluation/evaluator.py`）只接收预测和测试段数据，与模型无关。完整定义见[平台接口](平台接口.md)第 7 节。

## 打分的样本

- 每个任务有一个 `eval_mask`，比较模型时只看它，所有模型共用同一批格子。
- `extra_eval_masks` 用同一份预测在别的掩码上另外打分，作为补充，不能拿来和 `eval_mask` 的数字直接比较。
- 有效格的条件是掩码为真且真值有限。

## 指标（`metrics.json` → `scores.<掩码>`）

| 字段 | 含义 |
|---|---|
| `turbine` | 机组层，按格平均（micro）：`MAE_kW`、`RMSE_kW`、`NMAE_pct`（除以额定功率）、`ME_kW`、`n`；`macro_MAE_kW`（各机组 MAE 的平均）；`persistence_MAE_kW`；`SS_MAE_pct`、`SS_RMSE_pct`（相对持续法的降幅）；`over_frac`、`under_frac` |
| `farm` | 场站层：按发布时刻和时距把有效机组的误差相加，有效机组 ≥ 85% 的格才计入；`NMAE_pct` 除以这些机组的额定功率之和 |
| `per_horizon` | 各时距的 MAE、RMSE、NMAE、样本数、持续法 MAE |
| `report_horizons` | 任务 `report_horizons_minutes` 列出的时距 |
| `wind_bins` | 按目标时刻的实测风速分箱 |
| `stability_blocks` | 按发布时刻每 7 天一块的 MAE |
| `ramp_change_detection` | 无方向的大变化检测：真值或预测相对持续法的变化绝对值 ≥ 10% 额定功率时记为事件，两边同时出现算命中，报召回率、精确率、F1，以及真实事件格上的 MAE。预测的方向与真值相反也算命中，所以它只回答"大变化有没有被发现"，不能用来论证爬坡方向预测能力 |
| `ramp_directional` | 上升、下降各自的 `up`、`down`（事件、命中、召回率、精确率、F1），`direction_accuracy`（两边都有事件的格里方向一致的比例），`amplitude_bias_kW`（真实事件格上预测变化幅度减真实变化幅度的均值） |
| `daily_energy` | 只用 h=1 的预测，按目标时刻的日历日汇总电量误差；仅在 `eval_stride` 为 1 步时计算。电量只对"可评分的时间×机组格"求和，实际与预测用同一批格子，不是完整场站日电量。没有任何可评分格的日期不计入（`n_days_no_valid_cell`）；每天记录 `valid_cells`、`expected_cells`、`coverage`；覆盖率低于 `farm_min_valid_frac` 的日期计入 `n_days_below_min_coverage`，`covered` 给出只含达标日的 MAE 和 MAPE。首尾不完整的日期覆盖率自然偏低 |
| `sanity` | 负值比例、超额定比例 |
| `per_entity_MAE_kW` | 各机组的 MAE |

持续法在两者都有效的格上与模型比较。持续法的取值是窗口内最后一个有效的 `target_input`。

## 结果文件

单次运行目录下有 `run.json`、`metrics.json`、`per_horizon.csv`、`train.log`，可选 `predictions.npz` 和 `checkpoint.pt`，最后写 `DONE`。

`DONE` 是原子写入的 JSON 清单：运行身份哈希、三个必需文件（`run.json`、`metrics.json`、`per_horizon.csv`）的 SHA256、可选文件的大小。只有清单与目录内容全部吻合才算完成；缺文件、文件被改动，或来自旧版的只含 metrics 哈希的 `DONE`，都不算完成。每次运行开始前先清除同一目录里上一次的全部产物，运行期间目录里有 `RUNNING` 文件，第二个进程会被拒绝。

`run.json` 记录：

- 任务配置、模型参数、种子；
- `identity`：这些再加数据哈希合成的运行身份。批跑续跑时拿它与当前配置比较，不一致就拒绝复用（`--rerun-stale` 才会重做）；
- 数据集 `panel.parquet` 的 SHA256（运行时按文件重新计算并与 `meta.json` 比对）、元数据哈希 `dataset_meta_sha256`（额定功率、单位、掩码定义、分辨率等）、代码 SHA256、Git 提交号、软件版本；
- 耗时、参数量、验证指标、缩放参数；
- 用于汇总表的 `summary`。

## 外部预测

在别处跑出的预测存成 `predictions.npz`，包含：

- `predictions [I,H,N]`，float32，kW；
- `issue_times [I]`，int64，自 1970-01-01 起的微秒数；
- `entities [N]`。

然后执行 `wpf-benchmark score --task <任务> --predictions <文件> --out <目录>`。发布时刻和机组顺序必须与该任务的测试网格完全一致。网格可以从任何一次带 `--save-predictions` 的运行结果里取得。
