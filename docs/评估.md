# 评估

评估器（`evaluation/evaluator.py`）只接收预测和测试段数据，与模型无关。完整定义见[平台接口](平台接口.md)第 7 节。

## 打分的样本

- 每个任务有一个 `eval_mask`，比较模型时只看它，所有模型共用同一批格子。
- `extra_eval_masks` 用同一份预测在别的掩码上另外打分，作为补充，不能拿来和 `eval_mask` 的数字直接比较。
- 有效格的条件是掩码为真且真值有限。

## 指标（`metrics.json` → `scores.<掩码>`）

| 字段 | 含义 |
|---|---|
| `turbine` | 机组层，按格平均（micro）：`MAE_kW`、`RMSE_kW`、`NMAE_pct`（除以额定功率）、`ME_kW`、`n`；`macro_MAE_kW`（各机组 MAE 的平均）；`persistence_MAE_kW`；`SS_MAE_pct`、`SS_RMSE_pct`（相对持续法的降幅）；`over_frac`、`under_frac` |
| `farm` | 场站层：按发布时刻和时距把有效机组的误差相加，有效机组 ≥ 85% 的格才计入；`NMAE_pct` 除以这些机组的额定功率之和 |
| `per_horizon` | 各时距的 MAE、RMSE、NMAE、样本数、持续法 MAE |
| `report_horizons` | 任务 `report_horizons_minutes` 列出的时距 |
| `wind_bins` | 按目标时刻的实测风速分箱 |
| `stability_blocks` | 按发布时刻每 7 天一块的 MAE |
| `ramp` | 真值或预测相对持续法的变化 ≥ 10% 额定功率时记为爬坡，报召回率、精确率、F1，以及真实爬坡格上的 MAE |
| `daily_energy` | 只用 h=1 的预测，按目标时刻的日历日汇总电量误差；仅在 `eval_stride` 为 1 步时计算 |
| `sanity` | 负值比例、超额定比例 |
| `per_entity_MAE_kW` | 各机组的 MAE |

持续法在两者都有效的格上与模型比较。持续法的取值是窗口内最后一个有效的 `target_input`。

## 结果文件

单次运行目录下有 `run.json`、`metrics.json`、`per_horizon.csv`、`train.log`，可选 `predictions.npz` 和 `checkpoint.pt`，最后写 `DONE`。`run.json` 记录：

- 任务配置、模型参数、种子；
- 数据集 `panel.parquet` 的 SHA256、代码 SHA256、Git 提交号、软件版本；
- 耗时、参数量、验证指标、缩放参数；
- 用于汇总表的 `summary`。

## 外部预测

在别处跑出的预测存成 `predictions.npz`，包含：

- `predictions [I,H,N]`，float32，kW；
- `issue_times [I]`，int64，自 1970-01-01 起的微秒数；
- `entities [N]`。

然后执行 `wpf-benchmark score --task <任务> --predictions <文件> --out <目录>`。发布时刻和机组顺序必须与该任务的测试网格完全一致。网格可以从任何一次带 `--save-predictions` 的运行结果里取得。
