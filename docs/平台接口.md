# 平台接口规范

本文是数据集、任务、模型、评估和批跑之间的约定。新增数据集或模型时，只需遵守本文，不改平台主体。

## 1. 目录

```
src/wpf_benchmark/
  paths.py            项目目录：data/datasets、data/raw、results
  data/store.py       数据集存储读写（panel.parquet + meta.json）
  data/panel.py       Panel：完整时间网格上的 [T,N] 数组
  datasets/           数据集适配器（sdwpf、greenbyte），注册表
  tasks/config.py     TaskConfig：任务定义（JSON）
  tasks/windows.py    切分、发布时刻、ForecastBatch
  tasks/scaling.py    仅训练段的 min/max 缩放
  models/             Forecaster 基类、注册表、各模型
  models/neural/      NeuralForecaster 共用训练循环与各网络
  evaluation/         指标与评估器
  runner.py           单次运行：任务×模型×种子
  study.py            矩阵批跑、续跑、打包
  cli.py              命令行入口 wpf-benchmark
configs/tasks/        任务 JSON
configs/models/       模型参数 JSON
configs/studies/      批跑计划 JSON
```

## 2. 数据集存储

每个数据集一个目录 `data/datasets/<name>/`，包含：

- `panel.parquet`：长表，按 `(time, entity)` 排序，构成完整的规则时间网格；没有观测的格子也有一行，数值为 NaN。
  - `time`：`timestamp[us]`，UTC，标在区间起点（`time=T` 表示 `[T, T+Δ)` 的平均）。
  - `entity`：字符串，机组编号。
  - 变量列：`float32`，物理单位。
  - 掩码列：`bool`，列名以 `mask__` 开头，例如 `mask__m1`。
- `meta.json`：见下。
- `build_report.md`：构建过程统计（行数、缺失、去重、各掩码比例）。
- `fit.npz`（可选）：构建时拟合的对象，例如 SDWPF 清洗用的功率曲线和残差尺度。

`meta.json` 字段：

| 字段 | 含义 |
|---|---|
| `store_version` | 存储格式版本，当前为 1 |
| `name`, `title`, `adapter`, `adapter_version` | 数据集名称和构建它的适配器 |
| `resolution_minutes` | 时间分辨率 |
| `time_convention` | 固定为 `interval_start`，时区 `UTC` |
| `nominal_dates` | `true` 表示日期是名义的（SDWPF 只有第几天，Day 1 记为 1970-01-01） |
| `time_range` | `[start, end)`，网格范围 |
| `entities` | 列表；每项 `id`、`rated_kw`，可选 `lat`/`lon`/`x`/`y`、`hub_height_m`、`model`、`cod` |
| `variables` | `{name: {unit, description, source}}` |
| `masks` | `{name: {target, description, fit_window}}`；`target` 是该掩码对应的真值变量；`fit_window` 是构建掩码时拟合参数所用的时段，没有就写 `null` |
| `default_target` | 默认目标变量 |
| `sources` | 原始文件列表，每项 `path`、`bytes`、`sha256` |
| `panel_sha256` | `panel.parquet` 的 SHA256 |
| `build` | 构建参数、时间、代码版本 |
| `fit_window` | 构建时拟合清洗参数所用的时段（SDWPF 为前 196 天），没有则为 `null`。任务的验证段和测试段不得与它重叠，运行时检查 |

读取：`load_panel(name, columns, start, end)` 返回 `Panel`：

```python
Panel(meta, times: datetime64[us] [T], entities: list[str] [N],
      values: {变量: float32[T,N]}, masks: {掩码: bool[T,N]})
```

## 3. 任务（`configs/tasks/*.json`）

```json
{
  "name": "kelmarsh_actual_6h",
  "dataset": "kelmarsh",
  "target": "power",
  "target_input": "power",
  "inputs": ["wind_speed", "wind_dir_sin", "wind_dir_cos", "power"],
  "history_minutes": 1440,
  "horizon_minutes": 360,
  "train_stride_minutes": 60,
  "eval_stride_minutes": 10,
  "splits": {"train": ["2016-04-15", "2022-01-01"],
             "valid": ["2022-01-01", "2023-01-01"],
             "test":  ["2023-01-01", "2025-01-01"]},
  "train_mask": "observed",
  "valid_mask": "observed",
  "eval_mask": "observed",
  "extra_eval_masks": [],
  "report_horizons_minutes": [60, 120, 360]
}
```

- 时间区间都是左闭右开。所有长度以分钟写，按数据集分辨率换算成步数，不能整除时报错。
- `target`：真值变量。`train_mask`、`valid_mask`、`eval_mask` 在 `meta.masks` 里登记的 `target` 必须等于它。
- `target_input`：输入里代表"目标过去值"的变量，供持续法、Ridge、残差类网络使用。SDWPF 的 M2 任务真值是 `power_obs`，输入用清洗后的 `power`，所以两者可以不同。
- `extra_eval_masks`：同一份预测在别的掩码上另外打分，每项 `{"mask": 名称, "target": 真值变量}`。比较模型时只看 `eval_mask`。
- 可选字段：`future_inputs`（NWP 等未来已知输入，见第 9 节）、`rated_kw`（不写则用机组表）、`farm_min_valid_frac`（默认 0.85）、`wind_variable`（风速分箱用，默认 `wind_speed`）、`wind_bins`、`ramp_threshold_frac`（默认 0.10）、`stability_block_days`（默认 7）。

## 4. 发布时刻与切分

记历史长度为 `L` 步，预测长度为 `H` 步。发布时刻 `t` 是能看到的最后一行；输入为 `t-L+1 … t` 这 `L` 行，目标为 `t+1 … t+H`。

- 每个切分段内，发布时刻和全部目标时刻都必须落在该段内。
- 训练段和验证段的历史只取本段数据：第一个发布时刻是段内第 `L-1` 行，之后按 `train_stride` 取。
- 测试段的历史可以取测试段之前的数据：第一个发布时刻是测试段第 0 行，之后按 `eval_stride` 取。
- 每段最后一个发布时刻满足 `t+H` 不超出该段。
- 这条规则和旧 SDWPF 协议的取法一致。

### 时间标签的含义（接入 NWP 之前必须按此对齐）

数据的 `time=T` 表示区间 `[T, T+Δ)` 的平均，所以"发布时刻 `t`"这个标签在现有代码里有两层意思，需要分开：

| 量 | 含义 | 现有代码里的取值 |
|---|---|---|
| `sample_interval_start` | 一行数据所代表区间的起点 | 数据的 `time` 列，`t` 行就是 `t` |
| `observation_available_time` | 这一行的平均值最早何时算完 | `t + Δ`（区间结束时刻，不含数据上送和入库延迟） |
| `issue_time` | 平台保存的发布时刻标签 | `t`，即最后一行输入的区间起点 |
| `target_interval_start/end` | 第 `h` 个目标的区间 | `[t + hΔ, t + (h+1)Δ)` |

后果：
- 最后一行输入覆盖 `[t, t+Δ)`，第一个目标覆盖 `[t+Δ, t+2Δ)`，二者首尾相接。对于纯历史任务，只有在全部历史输入已于实际发布时刻可用，且预处理没有使用该时刻之后的信息的前提下，才能将其解释为无前视的下一时段预测。本段说明时间标签关系，不代替实际数据可用性核查。
- 保存的 `issue_time` 比真实可发布时刻早一个步长 `Δ`。如果用它去对齐外部信息（NWP 的 `available_time`、调度截止时间），会把本来尚未发生的信息当成可用，或者把实际可用的信息排除掉。
- 真实 SCADA 的上送延迟没有在本平台核实，上表的 `observation_available_time` 是下限。
- 时距 `h` 的分钟数是 `h × Δ`，即目标区间起点减 `issue_time`（`t`）。若以 `t+Δ` 为真实发布时刻，第 1 个目标的提前量为 0，按区间终点算则为 `Δ`。对外报告提前时间时要写明用的是哪一种。

现状：代码保持原有取值，`issue_time` 仍记 `t`，已有预测文件和结果不受影响。接入 NWP 时，应先明确真实发布时刻并核对历史观测已可用，再以该真实发布时刻筛选预报；`observation_available_time` 只是观测可用时刻的下限。届时再把上表的四个量作为独立字段写入 `SplitData` 和预测文件。旧 SDWPF 协议保留现有规则，作为 legacy。

`SplitData`（`tasks/windows.py`）是一段数据在内存里的样子：

```python
SplitData(name, times[T'], entities[N],
          inputs float32[T',N,F]  物理单位，缺失为 NaN,
          target float32[T',N]    真值变量,
          target_mask bool[T',N]  该段所用掩码,
          issues int64[I]         发布时刻在 times 中的下标,
          future: Optional[...])
```

`T'` 包含测试段前面借来的 `L-1` 行历史，`times[issues]` 才是发布时刻。

`ForecastBatch`：

```python
ForecastBatch(x_past float32[B,L,N,F], past_observed bool[B,L,N,F],
              issue_time datetime64[B], entities[N],
              x_future Optional[float32[B,H,N,K]] = None,
              y Optional[float32[B,H,N]] = None, y_mask Optional[bool[B,H,N]] = None)
```

`TaskContext` 在 `fit` 时交给模型：`input_names`、`target`、`target_input`、`target_input_index`、`L`、`H`、`resolution_minutes`、`steps_per_day`、`entities`、`rated_kw float32[N]`、`scaler`。

`Scaler`：只用训练段的行，按变量求 min/max（忽略 NaN）。`scale(x, name)` 返回 `(x-min)/max(max-min, 1e-6)`，`unscale` 反之。目标的缩放沿用 `target_input` 的 min/max；没有 `target_input` 时用训练段真值的 min/max。旧代码就是这样处理的。

## 5. 模型（`models/`）

```python
class Forecaster:
    name: str                      # 注册名，由 @register_model 设置
    supports_future_inputs = False
    def __init__(self, **params): ...
    @property
    def params(self) -> dict       # 实际生效的超参数，写进结果
    @property
    def deterministic(self) -> bool  # True 时批跑只跑一个种子
    def fit(self, ctx: TaskContext, train: SplitData, valid: SplitData) -> None
    def predict(self, batch: ForecastBatch) -> np.ndarray  # float32[B,H,N]，kW
    n_params: int                  # 可训练参数量，没有就是 0
    validation_metrics: Optional[dict]
```

- 输入特征一律按名称取：`ctx.input_names.index("power")`。模型里不得写死特征个数或位置。
- 模型可实现 `validate_context(ctx)`，只检查输入、历史长度和预测长度等兼容性，不训练、不修改状态；预检查和 `fit` 共用它。神经网络还会在预检查中执行小批量前向。
- 输入是物理单位，缺失为 NaN。需要缩放的模型自己调用 `ctx.scaler`。
- 输出必须是有限值，形状 `[B,H,N]`，单位与真值相同。是否截到 `[0, rated_kw]` 由模型决定，神经网络、Ridge、LightGBM 都截，持续法类不截。
- 模型的超参数放在 `configs/models/<name>.json` 的 `params` 里，`__init__` 收到未知参数时报错。
- 注册：在 `models/__init__.py` 里导入模块，用 `@register_model("name")` 注册。

## 6. 神经网络（`models/neural/`）

`NeuralForecaster` 提供共用训练循环，子类只写网络：

```python
@register_model("tcn")
class TCNForecaster(NeuralForecaster):
    layout = "entity"          # "entity"：每台机组独立建模；"graph"：所有机组一起输入
    default_params = {...}     # 网络超参数的默认值
    def build_network(self, spec: NetworkSpec) -> torch.nn.Module: ...
```

`NetworkSpec`：`L`、`H`、`F`（输入特征数）、`N`（机组数）、`input_names`、`target_input_index`（可能为 `None`）、`target_zero`（0 kW 在缩放后的值）、`params`（本模型的超参数字典）。

网络 `forward` 的输入输出（都是缩放后的值，缺失已置 0）：

| layout | 输入 | 输出 |
|---|---|---|
| `entity` | `[B', L, F]`，`B'` 是"发布时刻×机组"的组合 | `[B', H]` |
| `graph` | `[B, L, N, F]` | `[B, H, N]` |

`raw_inputs = True` 的网络会收到保留 NaN 的输入，自己处理缺失，例如 AGCRN 的当前功率残差分支要找最后一个有效功率。

共用训练参数（所有神经网络都有，写在 `params` 里）：`lr`（1e-3）、`weight_decay`（0）、`batch`（256；graph 布局按发布时刻计数）、`epochs`（30）、`patience`（5）、`loss`（`mse` 或 `mae`）。训练循环沿用旧代码：Adam 优化器；只在 `target_mask` 为真的目标上算损失；按验证损失早停，恢复最好的那一轮；预测时反缩放并截到 `[0, rated_kw]`。

检查点（`checkpoint.pt`，格式版本 2）保存：模型名、`params`、任务配置、`input_names`、缩放参数、机组顺序、`state_dict`、验证指标和来源信息。只存张量和普通 Python 值，用 `torch.load(weights_only=True)` 读取。

## 7. 评估（`evaluation/`）

评估器只接收预测 `float32[I,H,N]` 和测试段 `SplitData`，与模型无关。对 `eval_mask` 和每个 `extra_eval_masks` 分别打分：

- 有效格：掩码为真且真值有限。
- **机组层**：所有有效格的 MAE、RMSE、NMAE（除以该机组额定功率）、平均误差 ME，按格平均（micro）；另报各机组 MAE 的平均（macro）。
- **场站层**：按发布时刻和时距，把有效机组的误差相加；有效机组占比 ≥ `farm_min_valid_frac` 的格才计入。NMAE 除以这些有效机组的额定功率之和。
- **技能分**：相对持续法的 MAE 降幅。持续法 = 窗口内最后一个有效 `target_input`，在两者都有效的格上比较。
- **分时距**：每个时距的 MAE、RMSE、样本数；`report_horizons_minutes` 列出的时距在汇总表里单列。
- 有对应字段时另算：按实测风速分箱、按 `stability_block_days` 分块、大变化检测 `ramp_change_detection`（真值或预测相对持续法的变化绝对值 ≥ `ramp_threshold_frac × rated_kw` 即为事件，不看方向）和方向性指标 `ramp_directional`（上升、下降各自的 P/R/F1、方向一致率、幅度偏差）、日电量误差（h=1，按目标时刻的日历日汇总，排除没有可评分格的日期，并记录每日覆盖率）、负值和超额定比例。

外部预测（如在别处跑的基础模型）用 `wpf-benchmark score --task <任务> --predictions <npz>` 打分。npz 里要有 `predictions [I,H,N]`、`issue_times [I]`、`entities [N]`，必须和该任务的测试网格完全一致，否则报错。

## 8. 运行与批跑

单次运行目录 `results/runs/<task>/<model>/seed<k>/`（批跑时放在 `results/studies/<study>/runs/` 下）：

| 文件 | 内容 |
|---|---|
| `run.json` | 任务、模型参数、种子、`identity`（运行身份哈希及其组成）、按文件核验过的数据集 SHA256 和元数据哈希、代码 SHA256、环境版本、耗时、参数量 |
| `metrics.json` | 第 7 节全部指标 |
| `per_horizon.csv` | 各掩码 × 各时距的 MAE、RMSE、样本数 |
| `train.log` | 训练日志 |
| `predictions.npz` | 可选（`--save-predictions`），float32，压缩 |
| `checkpoint.pt` | 神经网络才有 |
| `DONE` | 最后原子写入的 JSON 清单：运行身份哈希、`run.json`、`metrics.json`、`per_horizon.csv` 的 SHA256、可选文件大小；续跑时据此判断已完成，且身份必须与当前配置一致 |
| `RUNNING` | 运行期间存在的锁文件，防止两个进程写同一目录；正常结束或报错退出时删除 |

批跑计划（`configs/studies/*.json`）：

```json
{"name": "baselines_v1",
 "tasks": ["sdwpf_m1_legacy", "kelmarsh_actual_6h"],
 "models": ["persistence", "ridge", "lightgbm", "lstm"],
 "seeds": [0, 1, 2],
 "save_predictions": false}
```

- 运行组合是任务 × 模型 × 种子；`deterministic` 为真的模型只跑第一个种子。
- `wpf-benchmark study --plan <计划> --preflight` 核验数据文件、三个切分的实际预测窗口和有效标签，检查模型与任务的兼容性，并对神经网络执行小批量前向，不训练。有问题时列出详情并返回退出码 1。
- 去掉 `--preflight` 开始运行。中断后重跑同一条命令，有 `DONE` 且校验通过的组合跳过。单个组合失败只记入 `failures.json`，不中断其他组合。
- 计划第一次运行时记下代码和数据集的 SHA256。续跑时如果不一致就停下，除非加 `--allow-changed-code`。
- 结束时写 `summary.csv`，并打包 `<study>_delivery.zip`：内含计划、`summary.csv`、各组合的 `run.json`、`metrics.json`、`per_horizon.csv`、`train.log`。预测和检查点默认不打包。

## 9. 未来已知输入（预留，NWP）

预留的 `align_forecasts` 函数读取 `issue_time`、`available_time`、`valid_time`、`entity` 和预报变量，在调用方传入的时刻中选择 `available_time` 不晚于该时刻的最新预报。它尚未接入任务：目前任务配置出现 `future_inputs` 会被明确拒绝。正式接入时，筛选时刻必须是第 4 节定义的真实发布时刻，不能直接传入现有预测文件里的区间起点标签；目标区间时间也须同步显式对齐。当前仅有函数的合成数据测试。
